# cores/regular — минимальное ядро (v1)

Дата: 2026-08-16
Статус: черновик на согласование

## 1. Что это и зачем

`cores/regular` — первое, «обычное» ядро исполнения скриптов платформы wire-auto.
Ядро **не интерпретирует языки само**. Оно исполняет скрипты как внешние процессы и
разговаривает с ними по единому протоколу. Задача v1 — доказать «позвоночник»
архитектуры: три манифеста → рукопожатие → спавн процесса → диалог по протоколу →
результат. Железа (serial/ssh/usb) в v1 **нет** — на доказанный позвоночник оно
навешивается следующим шагом одинаково для всех языков.

Модель исполнения — **out-of-process**: каждый скрипт запускается отдельным процессом,
общается с ядром через stdin/stdout. Падение скрипта не роняет ядро; язык скрипта ядру
безразличен — важно лишь, что на нём есть тонкий шим, говорящий протокол.

### Ключевая идея «моста к любому языку»

Мы не встраиваем N интерпретаторов. Мы задаём **один протокол на проводе** (JSON Lines
поверх stdio), а каждый язык получает тонкий SDK-шим (~100 строк), который читает/пишет
сообщения. «N языков × M возможностей» сводится к «1 протокол + N шимов + M бриджей».

## 2. Три слоя манифестов (главный контракт)

Каждый уровень декларирует себя манифестом (TOML). Рантайм — тот, кто их **сводит**.

### runtime.manifest
Кто такой рантайм и что он держит.
```toml
name = "wire-auto-runtime"
version = "0.1.0"
protocols = [1]          # версии протокола моста, которые рантайм умеет
cores = ["regular"]      # какие ядра зарегистрированы
```

### core.manifest (regular)
Что ядро даёт скриптам и что требует от рантайма.
```toml
name = "regular"
version = "0.1.0"
coreApi = 1              # версия контракта ядра для скриптов
protocol = 1            # версия протокола моста, на которой ядро говорит
provides = []           # возможности для скриптов; в v1 пусто (железа нет)
links = ["stdio"]       # связи (транспорты), по которым ядро говорит протокол
```

### script.manifest
Под что скрипт адаптирован и что ему нужно.
```toml
name = "hello"
version = "0.1.0"
core = "regular"        # под какое ядро адаптирован
coreApi = 1             # версию контракта ядра, которую скрипт понимает
link = "stdio"          # по какой связи подключается
cmd = ["python", "main.py"]  # чем себя запустить (ядро не знает про языки)
language = "python"     # необязательная метка для клиента (не гейтит)
capabilities = []       # что попросит у железа; в v1 обязано быть пусто
```

Формат манифестов одинаков по духу на всех трёх уровнях: `name`, `version` и поля
совместимости. Это осознанно — единый ментальный образ «у всего есть паспорт».

## 3. Рукопожатие (сведение контрактов)

**Глобальное правило рантайма №1: запуск только при полном сведении трёх манифестов.**
Перед спавном рантайм проверяет сверху вниз, и при первом несведении — **не запускает**
и возвращает клиенту машиночитаемую причину:

1. Скрипт просит `core = "regular"` → такое ядро есть в `runtime.cores`? Иначе → `UNKNOWN_CORE`.
2. `script.coreApi` совпадает с `core.coreApi`? Иначе → `CORE_API_MISMATCH`.
3. Каждая из `script.capabilities` входит в `core.provides`? Иначе → `CAPABILITY_DENIED`
   (в v1 обе стороны пусты — правило проверяется, но всегда проходит).
4. `core.protocol` входит в `runtime.protocols`? Иначе → `PROTOCOL_UNSUPPORTED`.
5. `script.link` входит в `core.links`? Иначе → `LINK_UNSUPPORTED`.
   Ядро определяется транспортом (связью), а не языком: как запустить процесс,
   знает сам скрипт (`cmd`), ядро лишь спавнит и подключается по связи, отдавая
   язык-агностичный `WIRE_SDK_DIR` (корень SDK-шимов).

Результат рукопожатия (успех со сведёнными версиями, либо код+описание ошибки) —
то, что клиент в `apps/` рисует как «светофор совместимости» ещё до запуска.

## 4. Протокол моста (v1)

Транспорт: **JSON Lines** — одно сообщение = одна строка JSON + `\n` — в обе стороны
через stdin/stdout процесса скрипта. Человекочитаемо, парсится в любом языке, легко
дебажить. Позже тело можно свапнуть на бинарный формат, рамка не изменится.

**Глобальное правило рантайма №2:** скрипт общается с миром *только* этими сообщениями.
stdout — канал протокола, а не «печать». Хочешь вывести текст — шли `log`, не `print`.

Каждое сообщение: `{ "type": <string>, ... }`. Набор v1:

| Направление      | type       | Назначение                                        |
|------------------|------------|---------------------------------------------------|
| runtime → script | `hello`    | старт: конфиг, сведённые версии, аргументы         |
| script → runtime | `ready`    | шим поднялся, готов работать                        |
| script → runtime | `log`      | строка вывода для клиента (`level`, `message`)      |
| script → runtime | `done`     | завершение: `exitCode`, опционально `result`        |
| runtime → script | `cancel`   | просьба завершиться (по кнопке/таймауту)            |

`request`/`response` (запрос возможностей железа) в протоколе **зарезервированы**, но в v1
не используются: у ядра `provides = []`, любой `request` от скрипта → ядро отвечает ошибкой
`CAPABILITY_DENIED` и это фиксируется как нарушение контракта.

### Пример диалога
```
runtime → {"type":"hello","protocol":1,"coreApi":1,"args":[]}
script  → {"type":"ready"}
script  → {"type":"log","level":"info","message":"hello from python"}
script  → {"type":"done","exitCode":0}
```

## 5. Жизненный цикл исполнения

1. **Discover** — рантайм читает `script.manifest`, находит ядро `regular` по его манифесту.
2. **Handshake** — сведение трёх манифестов (раздел 3). Провал → стоп с причиной.
3. **Spawn** — ядро через языковой адаптер (`python`) запускает `entry` с подключённым
   шимом; stdin/stdout — труба протокола, stderr — сырой лог для диагностики самого шима.
4. **Hello** — рантайм шлёт `hello`; ждёт `ready` в пределах `startupTimeout`.
5. **Run** — качает сообщения: `log` → наружу клиенту; `request` → в v1 отклоняет.
6. **Finish** — `done` от скрипта, либо `cancel`+kill по таймауту/кнопке, либо аварийная
   смерть процесса. Во всех случаях ядро выдаёт единый результат исполнения.

### Таймауты и остановка
- `startupTimeout` — не прислал `ready` вовремя → kill + `STARTUP_TIMEOUT`.
- `runTimeout` — не прислал `done` вовремя → `cancel`, затем kill → `RUN_TIMEOUT`.
- Ручная отмена из клиента → `cancel`, grace-период, затем kill.

## 6. Обработка ошибок

Единый результат исполнения (наружу клиенту), взаимоисключающие исходы:
- `OK` — `done` с `exitCode = 0`.
- `SCRIPT_ERROR` — `done` с `exitCode != 0` (ошибка внутри скрипта).
- `HANDSHAKE_FAILED` — с конкретным кодом из раздела 3.
- `PROTOCOL_VIOLATION` — битый JSON, неизвестный `type`, `request` при пустых `provides`.
- `STARTUP_TIMEOUT` / `RUN_TIMEOUT` — не уложился в тайминги.
- `CRASHED` — процесс умер без `done`.

Все коды — машиночитаемые enum + человекочитаемое сообщение. Клиент показывает,
логи пишутся структурно.

## 7. Границы v1 (что НЕ делаем)

- Нет бриджей железа (serial/ssh/usb/mqtt) и активных `capabilities`.
- Нет `request/response` в работе (зарезервированы в протоколе).
- Один язык-адаптер — `python`. Bash/Node — позже, по той же схеме.
- Нет сети/удалёнки: скрипт исполняется локально.
- Нет реестра community-скриптов: гоняем из папки.
- Нет жёсткой песочницы ОС (cgroups/seccomp) — только процессная изоляция + таймауты.
  Настоящий sandbox — отдельный этап, но граница «только через протокол» уже заложена.

## 8. Ориентировочная раскладка кода

```
runtime/
├── cmd/                 точка входа рантайма (CLI: запусти скрипт по пути)
├── internal/
│   ├── manifest/        чтение/валидация трёх TOML-манифестов
│   ├── handshake/       сведение контрактов (раздел 3)
│   ├── protocol/        типы сообщений JSON Lines, кодек, чтение потока
│   └── exec/            спавн процесса, качание протокола, таймауты, kill
cores/
└── regular/
    ├── core.manifest    манифест ядра (TOML)
    ├── adapters/
    │   └── python/      как запустить python-скрипт + доставить шим
    └── sdk/
        └── python/      тонкий шим: читает hello/cancel, шлёт ready/log/done
scripts/
└── examples/
    └── hello/
        ├── script.manifest
        └── main.py      использует python-шим, печатает "hello from python"
```
(Точное расположение `protocol/` и `sdk/` относительно `runtime` vs `cores` уточним при
написании плана — по guide `runtime/` держит внешний протокол и SDK; языковой шим ядра
логично рядом с ядром. Границу проведём в implementation-плане.)

## 9. Критерии готовности v1

- `runtime` запускает `scripts/examples/hello` и получает `hello from python` как `log`,
  затем `OK`.
- Подмена `script.coreApi` на `2` → запуск отклонён с `CORE_API_MISMATCH` до спавна.
- Объявленный `capabilities = ["serial"]` в скрипте → отклонён с `CAPABILITY_DENIED`.
- Скрипт-«зависалка» без `done` → убит по `runTimeout` с `RUN_TIMEOUT`.
- Любой `request` от скрипта → `PROTOCOL_VIOLATION` (провода железа ещё нет).

## 10. Открытые вопросы на будущее (вне v1)

- Форма `provides`/`request` для железа: адресация устройств, права, арбитраж `COM3`.
- Второе ядро `cores/raw` (доверенный прямой доступ) как осознанный уровень доверия.
- Бинарный транспорт (MessagePack) при упоре в скорость.
- Реестр community-скриптов и подпись манифестов.

## 11. Полиморфная стыковка runtime↔core (v1.1)

Рантайм дружит с **несколькими ядрами** и стыкуется с ними **по контракту, а не по
имени** (полиморфизм / утиная типизация на границе компонентов). Каждый компонент
публикует «что даёт» и «что требует»; двое совместимы, если взаимно удовлетворяют.

**Рантайм объявляет транспорты**, которые физически умеет водить:
```toml
# runtime.manifest
transports = ["stdio"]
```

**Допуск ядра (admission).** Рантайм сканирует `cores/*/core.manifest` и допускает
ядро `C`, если:
1. `C.protocol ∈ runtime.protocols` — общая версия протокола;
2. `C.links ∩ runtime.transports ≠ ∅` — рантайм умеет хотя бы одну связь ядра.

Несовместимые ядра не регистрируются, но причина сохраняется (для клиента):
«ядро X хочет протокол 2, рантайм говорит [1]» / «связь socket, рантайм умеет [stdio]».

**Маршрутизация.** Скрипт роутится по `scr.Core` к допущенному ядру; затем обычное
трёхстороннее рукопожатие идёт против **этого** ядра, а `sdk`/possibilities берутся
из его папки. Имя-allowlist `runtime.cores` больше не гейт — источник истины теперь
реестр допуска; в рукопожатии остаётся лишь `scr.Core == core.Name`.

**Коды.** `UNKNOWN_CORE` — нет ядра с таким именем; `CORE_INCOMPATIBLE` — ядро есть,
но его контракт не сошёлся с рантаймом.

**«Пересаживание».** Скрипт меняет одно поле `core` в своём манифесте и едет на другое
допущенное ядро; рантайм не трогается. Тот же принцип зеркалится на `app ↔ script`.

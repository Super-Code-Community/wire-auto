# Рукопожатие — сведение двух манифестов

**Правило бандла №1:** запуск скрипта происходит только при полном сведении двух
манифестов (`core.manifest` и `script.manifest`). Бандл проверяет сверху вниз;
при первом несведении — **не запускает** и возвращает клиенту машиночитаемую причину.

> Нет отдельного рукопожатия «runtime↔core» — рантайм встроен в бандл, допуска нет.
> Рукопожатий два: **app↔core** (протокол команд/событий) и **core↔script** (описано здесь).

## Порядок проверок

Проверки выполняются строго последовательно. Провал на любом шаге останавливает процесс.

### 1. Маршрутизация по имени ядра

Скрипт объявляет `core = "regular"`. Бандл ищет ядро с таким именем в своём реестре.

- Нет ядра с таким именем → **`UNKNOWN_CORE`**
- Ядро есть, но его контракт не совместим → **`CORE_INCOMPATIBLE`** (с причиной)

> Разница: `UNKNOWN_CORE` означает «такого имени нет вообще»; `CORE_INCOMPATIBLE` —
> «имя есть, контракт не сошёлся». Подробнее о бандлах — в [cores.md](cores.md).

### 2. Совместимость версии Core API

`script.coreApi` должен совпадать с `core.coreApi`.

- Несовпадение → **`CORE_API_MISMATCH`**

### 3. Возможности (capabilities)

Каждая capability из `script.capabilities` должна быть разрешена реестром возможностей
бандла (`capreg`). Авторизация не зависит от поля манифеста — `core.manifest` не содержит
поля `provides`.

- Хотя бы одна capability не разрешена → **`CAPABILITY_DENIED`**
- В v1 `capabilities = []`, правило всегда проходит.

### 4. Связь (link/transport)

`script.link` должен входить в `core.links`.

- Не входит → **`LINK_UNSUPPORTED`**

## Коды ошибок — сводная таблица

| Код                    | Причина                                               | Когда возникает           |
|------------------------|-------------------------------------------------------|---------------------------|
| `UNKNOWN_CORE`         | Нет ядра с именем из `script.core`                    | Шаг 1                     |
| `CORE_INCOMPATIBLE`    | Ядро есть, но его контракт не совместим               | Шаг 1                     |
| `CORE_API_MISMATCH`    | `script.coreApi` ≠ `core.coreApi`                    | Шаг 2                     |
| `CAPABILITY_DENIED`    | Скрипт требует capability, не разрешённую в capreg    | Шаг 3                     |
| `LINK_UNSUPPORTED`     | `script.link` ∉ `core.links`                          | Шаг 4                     |

## Результат рукопожатия

При провале бандл возвращает клиенту:
```json
{
  "Status": "HANDSHAKE_FAILED",
  "ErrorCode": "CORE_API_MISMATCH",
  "ErrorMessage": "script coreApi 2, core coreApi 1",
  "Logs": []
}
```

При успехе — структура `reconciled` со сведёнными версиями (`Protocol`, `CoreAPI`),
которая передаётся дальше в фазу исполнения.

Клиент в `apps/` может показать «светофор совместимости» **до** запуска скрипта,
используя те же проверки по манифестам — причина известна заранее.

## Пример: что происходит при изменении coreApi

Если в `script.manifest` поменять `coreApi = 2`, бандл вернёт:
```json
{
  "Status": "HANDSHAKE_FAILED",
  "ErrorCode": "CORE_API_MISMATCH",
  "ErrorMessage": "...",
  "Logs": []
}
```
Скрипт не будет запущен вообще — процесс не стартует.

# Рукопожатие — сведение трёх манифестов

**Правило рантайма №1:** запуск скрипта происходит только при полном сведении трёх
манифестов. Рантайм проверяет сверху вниз; при первом несведении — **не запускает**
и возвращает клиенту машиночитаемую причину.

## Порядок проверок

Проверки выполняются строго последовательно. Провал на любом шаге останавливает процесс.

### 1. Маршрутизация по имени ядра

Скрипт объявляет `core = "regular"`. Рантайм ищет допущенное ядро с таким именем
в реестре (реестр строится заранее сканированием `cores/*/core.manifest`).

- Нет ядра с таким именем → **`UNKNOWN_CORE`**
- Ядро есть, но его контракт был отклонён при допуске → **`CORE_INCOMPATIBLE`** (с причиной)

> Разница: `UNKNOWN_CORE` означает «такого имени нет вообще»; `CORE_INCOMPATIBLE` —
> «имя есть, но контракт runtime↔core не сошёлся». Подробнее о допуске —
> в [cores-and-runtimes.md](cores-and-runtimes.md).

### 2. Совместимость версии Core API

`script.coreApi` должен совпадать с `core.coreApi`.

- Несовпадение → **`CORE_API_MISMATCH`**

### 3. Возможности (capabilities)

Каждая capability из `script.capabilities` должна входить в `core.provides`.

- Хотя бы одна не входит → **`CAPABILITY_DENIED`**
- В v1 обе стороны пусты (`capabilities = []`, `provides = []`), правило всегда проходит.

### 4. Версия протокола моста

`core.protocol` должен входить в `runtime.protocols`.

- Не входит → **`PROTOCOL_UNSUPPORTED`**

### 5. Связь (link/transport)

`script.link` должен входить в `core.links`.

- Не входит → **`LINK_UNSUPPORTED`**

## Коды ошибок — сводная таблица

| Код                    | Причина                                               | Когда возникает           |
|------------------------|-------------------------------------------------------|---------------------------|
| `UNKNOWN_CORE`         | Нет допущенного ядра с именем из `script.core`        | Шаг 1                     |
| `CORE_INCOMPATIBLE`    | Ядро есть, но его контракт не сошёлся с рантаймом     | Шаг 1                     |
| `CORE_API_MISMATCH`    | `script.coreApi` ≠ `core.coreApi`                    | Шаг 2                     |
| `CAPABILITY_DENIED`    | Скрипт требует capability, которой нет у ядра         | Шаг 3                     |
| `PROTOCOL_UNSUPPORTED` | `core.protocol` ∉ `runtime.protocols`                 | Шаг 4                     |
| `LINK_UNSUPPORTED`     | `script.link` ∉ `core.links`                          | Шаг 5                     |

## Результат рукопожатия

При провале рантайм возвращает клиенту:
```json
{
  "Status": "HANDSHAKE_FAILED",
  "ErrorCode": "CORE_API_MISMATCH",
  "ErrorMessage": "script coreApi 2, core coreApi 1",
  "Logs": []
}
```

При успехе — структура `reconciled` со сведёнными версиями (`Protocol`, `CoreAPI`),
которая передаётся дальше в фазу исполнения.

Клиент в `apps/` может показать «светофор совместимости» **до** запуска скрипта,
используя те же проверки по манифестам — причина известна заранее.

## Пример: что происходит при изменении coreApi

Если в `script.manifest` поменять `coreApi = 2`, рантайм вернёт:
```json
{
  "Status": "HANDSHAKE_FAILED",
  "ErrorCode": "CORE_API_MISMATCH",
  "ErrorMessage": "...",
  "Logs": []
}
```
Скрипт не будет запущен вообще — процесс не стартует.

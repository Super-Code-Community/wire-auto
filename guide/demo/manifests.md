# Два манифеста — паспорта компонентов

Каждый уровень системы декларирует себя TOML-манифестом. Принцип «у всего есть паспорт» —
осознанный единый ментальный образ.

Файлы манифестов:
- `cores/regular/core.manifest` (и `cores/duplex/core.manifest`)
- `scripts/examples/hello/script.manifest` (и любой другой скрипт)

> Отдельного рантайм-манифеста **не существует** — рантайм встроен в бандл ядра как
> библиотека, а не является отдельным процессом с манифестом.

## core.manifest

Описывает ядро-бандл: что предоставляет скриптам и что требует для совместимости.

```toml
name = "regular"
version = "0.1.0"
coreApi = 1              # версия контракта ядра (скрипты объявляют совместимость с ней)
protocol = 1             # версия протокола моста core↔script
links = ["stdio"]        # связи, по которым ядро говорит протокол
```

| Поле       | Тип       | Назначение                                          |
|------------|-----------|-----------------------------------------------------|
| `name`     | string    | имя ядра (скрипт ссылается по этому имени в `core`) |
| `version`  | string    | версия ядра                                         |
| `coreApi`  | int       | версия контракта ядра                               |
| `protocol` | int       | версия протокола моста                              |
| `links`    | []string  | поддерживаемые связи (транспорты)                   |

> Поля `provides` в `core.manifest` **нет**. Возможности (capabilities) хранятся
> во внутреннем реестре бандла (`capreg`) — а не объявляются в манифесте.
> Авторизация capability проверяется по `capreg` при рукопожатии.

## script.manifest

Описывает скрипт: под что адаптирован и что ему нужно.

```toml
name = "hello"
version = "0.1.0"
core = "regular"         # на какое ядро нацелен (маршрутизация)
coreApi = 1              # версия контракта ядра, которую скрипт понимает
link = "stdio"           # по какой связи подключается
cmd = ["python", "main.py"]  # команда запуска (ядро не знает про языки)
language = "python"      # НЕОБЯЗАТЕЛЬНАЯ метка для клиента (не гейтит)
capabilities = []        # что запрашивает; проверяется по capreg ядра
```

| Поле           | Тип       | Обязательно | Назначение                                        |
|----------------|-----------|-------------|---------------------------------------------------|
| `name`         | string    | да          | имя скрипта                                       |
| `version`      | string    | да          | версия скрипта                                    |
| `core`         | string    | да          | целевое ядро (по имени из `core.manifest`)         |
| `coreApi`      | int       | да          | требуемая версия контракта ядра                   |
| `link`         | string    | да          | связь (должна входить в `core.links`)             |
| `cmd`          | []string  | да          | команда для запуска скрипта                       |
| `language`     | string    | **нет**     | информационная метка языка (только для клиента)   |
| `capabilities` | []string  | да          | запрашиваемые возможности (в v1 всегда `[]`)      |

> Поле `language` — **необязательная клиентская метка**. Ядро её не читает и не
> принимает никаких решений на основе `language`. Ядро язык-агностично по дизайну.
> Подробнее — в [transports-and-language-independence.md](transports-and-language-independence.md).

## Связь между манифестами

При каждом запуске бандл сводит оба манифеста в порядке проверок.
Подробнее — в [handshake.md](handshake.md).

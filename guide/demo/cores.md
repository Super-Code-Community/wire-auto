# Ядра — самодостаточные бандлы

## Что такое «ядро-бандл»

Каждое ядро — это **самодостаточный Go-модуль** (`cores/<имя>/`), который:
- встраивает рантайм-библиотеку через `internal/` (вендоринг)
- содержит исполняемую точку входа `cmd/core`
- декларирует себя через `core.manifest`

Нет отдельного «рантайм-процесса» — вы запускаете бинарь ядра напрямую.

```
cores/
├── regular/                 бандл 1 (Go-модуль wire-auto/cores/regular)
│   ├── go.mod
│   ├── core.manifest
│   ├── cmd/core/            точка входа — стриминговый мост app↔core
│   ├── internal/            встроенная рантайм-библиотека
│   └── sdk/
│       └── python/
│           ├── wire.py
│           └── wire_test.py
└── duplex/                  бандл 2 (Go-модуль wire-auto/cores/duplex)
    ├── go.mod
    ├── core.manifest
    ├── cmd/core/            точка входа — одиночный запуск (-script <dir>)
    └── internal/            встроенная рантайм-библиотека
```

## Два бандла

### cores/regular — стриминговый мост (протокол 1)

`cores/regular/cmd/core` — долгоживущий двусторонний мост: принимает команды
`list / run / cancel / exit` через stdin и шлёт события `catalog / ready / log / result / error`
через stdout. Это бэкенд `deview`.

### cores/duplex — одиночный запуск (протокол 2)

`cores/duplex/cmd/core` — запускает один скрипт по флагу `-script <dir>` и завершается.
Поддерживает возможность `env.get` (чтение переменных окружения).

## Два рукопожатия

Есть **два** рукопожатия, не три:

1. **app↔core** — клиентское приложение общается с бандлом по протоколу команд/событий.
2. **core↔script** — бандл спавнит скрипт и сводит манифесты перед запуском.

Старое рукопожатие «runtime↔core» (допуск) **удалено** — отдельного рантайм-манифеста
и реестра допуска не существует.

## Стыковка по контракту

Бандл стыкуется со скриптами **по контракту, а не по имени языка** (утиная типизация на
границе компонентов).

### Реестр возможностей (capreg)

Каждый бандл хранит внутренний реестр возможностей (`capreg`). При сведении манифестов
каждая capability из `script.capabilities` проверяется по `capreg` — а не по полю
`core.manifest.provides` (его нет).

### Маршрутизация скрипта (в regular)

Когда скрипт объявляет `core = "regular"`, бандл читает `script.manifest` и запускает
рукопожатие core↔script:

Варианты:
- Нет ядра с таким именем → **`UNKNOWN_CORE`**
- Ядро есть, контракт не сошёлся → **`CORE_INCOMPATIBLE`** (с причиной)

> `UNKNOWN_CORE` — «такого имени нет»; `CORE_INCOMPATIBLE` — «имя есть, контракт не сошёлся».

## «Пересаживание» скрипта

Скрипт меняет одно поле `core` в своём `script.manifest` и «едет» на другое ядро.
Клиентское приложение не трогается.

```toml
# было
core = "regular"

# стало — переедет на другое ядро
core = "duplex"
```

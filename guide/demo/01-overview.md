# Обзор wire-auto

wire-auto — платформа для запуска скриптов автоматизации на разных языках программирования
поверх единой шины: одинаково к железу (serial, ssh, usb), независимо от того, написан
скрипт на Python, Bash или Node.

## Принцип «ничего монолитного»

Ни один компонент не разрастается в «один большой файл». Каждый модуль, ядро, скрипт,
шим — отдельный артефакт со своим манифестом. Это применяется везде: к коду, к
документации (`guide/` — набор маленьких файлов), к манифестам (один файл — один паспорт).

## Две пары стыковки

Архитектура строится вокруг двух явных границ совместимости:

```
apps  ──(протокол/SDK)──▶  runtime  ──▶  cores  ──(бриджи)──▶  железо
  ▲                                                                │
  └────────────────────── результат/события ──────────────────────┘
```

**app ↔ runtime** — граница, через которую клиентское приложение запускает скрипты
и получает события/результат. Сейчас `apps/` пусты; первый клиент — CLI-команда
`wire`.

**runtime ↔ core** — граница, через которую рантайм допускает ядро и стыкуется с ним
по контракту. Скрипт объявляет `core = "regular"` и едет на соответствующее ядро.
Подробнее — в [cores-and-runtimes.md](cores-and-runtimes.md).

**runtime ↔ script** — граница исполнения: рантайм спавнит скрипт, общается по
JSON Lines протоколу. Подробнее — в [protocol.md](protocol.md) и [lifecycle.md](lifecycle.md).

## Зоны репозитория

```
wire-auto/
├── apps/        клиенты — браузер скриптов (desktop/web/tui, пока пустая зона)
├── runtime/     рантайм-модели: runtime/<модель>/  (сейчас runtime/basic/)
├── cores/       ядра исполнения: cores/<ядро>/     (сейчас cores/regular/)
├── packages/    общий переиспользуемый Go-код (пока пусто)
├── scripts/     сами скрипты: examples/ + community/
├── guide/       документация (эта папка)
└── docs/        внутренние спеки и ADR
```

`apps/`, `packages/` — зоны будущего роста; пока пусты, появятся с первыми клиентами
и переиспользуемыми пакетами.

## Общий поток данных (один запуск скрипта)

1. Клиент (`wire` CLI) передаёт путь к папке скрипта.
2. Рантайм читает `runtime.manifest`, сканирует `cores/` и допускает ядра.
3. Рантайм читает `script.manifest`, маршрутизирует скрипт на допущенное ядро.
4. Рукопожатие — сведение трёх манифестов. Любой конфликт → стоп с кодом причины.
5. Рантайм спавнит `cmd` из `script.manifest`, пробрасывает `WIRE_SDK_DIR`.
6. Диалог по JSON Lines: `hello` → `ready` → `log`* → `done`.
7. Клиент получает JSON-результат: `Status`, логи, опциональный `result`.

Детали — в [lifecycle.md](lifecycle.md).

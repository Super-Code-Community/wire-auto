# Обзор wire-auto

wire-auto — платформа для запуска скриптов автоматизации на разных языках программирования
поверх единой шины: одинаково к железу (serial, ssh, usb), независимо от того, написан
скрипт на Python, Bash или Node.

## Принцип «ничего монолитного»

Ни один компонент не разрастается в «один большой файл». Каждый модуль, ядро, скрипт,
шим — отдельный артефакт со своим манифестом. Это применяется везде: к коду, к
документации (`guide/` — набор маленьких файлов), к манифестам (один файл — один паспорт).

## Две границы стыковки

Архитектура строится вокруг двух явных границ совместимости:

```
apps  ──(протокол/SDK)──▶  cores  ──(бриджи)──▶  железо
  ▲                                                  │
  └──────────────── результат/события ───────────────┘
```

**app↔core** — граница, через которую клиентское приложение запускает скрипты
и получает события/результат. Это долгоживущий двусторонний мост поверх stdio (JSON Lines);
первый клиент — консольный `deview`. Подробнее — в
[app-core-bridge.md](app-core-bridge.md).

**core↔script** — граница исполнения: бандл ядра спавнит скрипт, общается по
JSON Lines протоколу. Подробнее — в [protocol.md](protocol.md) и [lifecycle.md](lifecycle.md).

## Зоны репозитория

```
wire-auto/
├── apps/        клиенты — браузер скриптов (deview и будущие)
├── cores/       ядра-бандлы: cores/<имя>/  (regular и duplex)
├── packages/    общий переиспользуемый Go-код (пока пусто)
├── scripts/     сами скрипты: examples/ + community/
├── guide/       документация (эта папка)
└── docs/        внутренние спеки и ADR
```

`packages/` — зона будущего роста; появится с переиспользуемыми пакетами.

## Общий поток данных (один запуск скрипта)

1. Клиент (например `deview`) передаёт команду `run` с путём к папке скрипта.
2. Бандл ядра читает `script.manifest` и маршрутизирует скрипт на нужное ядро.
3. Рукопожатие — сведение двух манифестов (`core.manifest` и `script.manifest`).
   Любой конфликт → стоп с кодом причины.
4. Бандл спавнит `cmd` из `script.manifest`, пробрасывает `WIRE_SDK_DIR`.
5. Диалог по JSON Lines: `hello` → `ready` → `log`* → `done`.
6. Клиент получает JSON-результат: `Status`, логи, опциональный `result`.

Детали — в [lifecycle.md](lifecycle.md).

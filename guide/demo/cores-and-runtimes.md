# Ядра и рантайм-модели

## Контейнеры моделей

И рантайм-модели, и ядра — **контейнеры**: самостоятельные папки с манифестом
и реализацией. Ни одно из них не «жёстко зашито» в другое.

```
runtime/
└── basic/                    рантайм-модель (Go-модуль wire-auto/runtime/basic)
    └── runtime.manifest

cores/
└── regular/                  ядро (папка с манифестом + шимы)
    └── core.manifest
```

Будущие модели (`runtime/cloud/`, `cores/raw/`) появятся рядом, не трогая существующие.

## Полиморфная стыковка по контракту

Рантайм стыкуется с ядрами **по контракту, а не по имени** (утиная типизация на
границе компонентов). Список `cores` в `runtime.manifest` — информационный, не гейт.

### Реестр допуска (Admission Registry)

При старте рантайм сканирует `cores/*/core.manifest` и **допускает** каждое ядро `C`,
если одновременно выполняются оба условия:

1. `C.protocol ∈ runtime.protocols` — общая версия протокола моста
2. `C.links ∩ runtime.transports ≠ ∅` — рантайм умеет хотя бы одну связь ядра

Несовместимые ядра **не регистрируются**, но причина сохраняется для диагностики.

Примеры причин отклонения:
- «ядро X хочет протокол 2, рантайм говорит [1]»
- «ядро Y хочет связь socket, рантайм умеет [stdio]»

### Маршрутизация скрипта

Когда скрипт объявляет `core = "regular"`, рантайм ищет это имя среди **допущенных** ядер:

```
script.core → admitted["regular"]?
```

Варианты:
- Есть допущенное ядро с таким именем → продолжить рукопожатие
- Нет никакого ядра с таким именем → **`UNKNOWN_CORE`**
- Ядро с таким именем есть, но было отклонено при допуске → **`CORE_INCOMPATIBLE`** (с причиной)

> `UNKNOWN_CORE` vs `CORE_INCOMPATIBLE` — принципиальная разница:
> первое — «такого имени нет вообще», второе — «имя есть, контракт не сошёлся».

После маршрутизации идёт стандартное трёхстороннее рукопожатие (см. [handshake.md](handshake.md)):
проверки coreApi, capabilities, protocol, link — уже против конкретного допущенного ядра.

## «Пересаживание» скрипта

Скрипт меняет одно поле `core` в своём `script.manifest` и «едет» на другое
допущенное ядро. Рантайм не трогается.

```toml
# было
core = "regular"

# стало — переедет на другое ядро, если оно допущено
core = "raw"
```

Тот же принцип зеркалится на уровне `app ↔ script`: скрипт меняет `core` —
и получает другой контекст исполнения без изменений в клиентском приложении.

## Текущее состояние (v1)

| Компонент        | Статус   | Протокол | Связи   |
|------------------|----------|----------|---------|
| runtime/basic    | активен  | [1]      | [stdio] |
| cores/regular    | допущен  | 1        | [stdio] |

Будущие ядра (например, `cores/raw` с прямым доступом) добавляются как новые папки
в `cores/` — рантайм подхватит их автоматически при следующем старте.
